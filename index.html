02 — Evals

How we know what works

Scout's First Eval System.

One scores retrieval with rule-based code. The other scores the whole agent's answer with an LLM-as-judge. Both run on a fixed set of queries so any change is measurable.

RAG eval rule-based

Runs queries through retrieval, then code inspects the top-K for freshness, topical match, and dupes. Used to validate retrieval changes (results · slide 3, deep dives · slides 4–8).

Evergreen (4): "how to train for your first marathon"
Chat eval LLM-as-judge

Runs the full Scout agent (RAG + WebSearchTool + Trailforks MCP) per candidate model. A judge LLM scores the answer. Used to A/B-test models (results · slide 3).

05 — Where binary metrics lie

Category · gear

BEFORE and AFTER both pass 4/4 — but the user-visible experience is very different.

On gear queries, BEFORE's binary check looks fine. A 2026 article is in the top-4. But if you read the top-1 result — which is what users actually see — BEFORE often serves a stale ancillary piece while AFTER surfaces the current buyer's guide.

Query (BEFORE "passes" deceptively)
best hiking boots this year

BEFORE · passes the check, fails the user

#1 "How to Break In Your Boots"2021
#2 Boot care guide2022
#3 Generic outdoor list2023
#4 Boots buyer's guide2026

AFTER · top-1 is what they came for

#1 Hiking boots buyer's guide2026
#2 Trail boots roundup2026
#3 Lightweight boots picks2025
#4 Boot care guide2022

Drivers: dedup by item_url + recency rerank push the 2026 roundups above older "how-to" content. Why dedup matters here: Pinecone holds multiple vectors per article — long pieces get chunked into ~400-token vectors. Without dedup, the top-K can be 4 chunks of the same 2021 article, with the 2026 buyer's guide invisible. Dedup collapses each URL to its best-scoring chunk; recency then promotes the 2026 piece. The year-injection rewrite also anchors the embedding on "2026".

Bridge user language to article language.

Query · evergreen

Rewritten to → training tips for first-time marathon runners in 2026

BEFORE · only 2 results cleared the threshold

#1 The Best Advice For First Time Marathoners2015-12

#5 The Best Advice For First Time Marathoners (was #1)2015-12

Why this is the canonical rewrite case: the user says "how to train"; the 2024 editorial piece is titled "Training Resolutions Coaches Wish You'd Make" — semantically related but lexically very different. Pure cosine on the raw query buries it. The rewrite to "training tips for first-time marathon runners" shares the "training tips" stem with "Training Resolutions" — a much closer cosine match. A wider candidate pool alone wouldn't have lifted this past the 2015 article whose title literally contains the user's wording. Rewrite is what changed the embedding direction enough for the modern editorial style to win.

07 — What's actually doing the work

The four techniques

Key drivers for retrieval improvements.

01

Wider candidate pool (top_k 4 → 40)

Most "missing recent content" cases were relevant 2024+ articles ranked just outside top-4 on pure cosine. Widening the pool brings them into reranking range.

02

Recency-weighted rerank (0.7·sim + 0.3·decay, 365d)

Once recent items are in the pool, the blended score lifts them above similarly-scored older items — without ignoring semantic relevance.

03

Dedup by item_url

One article can sit in Pinecone as 12+ vectors (chunks of long pieces + leftover chunks from indexer re-runs). Dedup collapses each item_url to its best-scoring chunk — turning the wider pool into more distinct articles, not 40 chunks of the same three.

04

LLM query rewrite (paraphrase + year + entity normalization)

Paraphrases user wording into editorial wording (marathon showcase, Slide 6). Injects the current year so "this year" anchors to 2026 (drove the 2026 TdF outlook). Normalizes entities — "Yosemite Valley" matched a broader National Parks roundup.

09 — The bigger picture

The takeaway

An agentic system isn't a model. It's the harness around one.

A decade ago, the Sculley paper made the point that ML code was a sliver of any real ML system — dwarfed by data plumbing, infrastructure, and monitoring. The same is true for agentic products today. The LLM is one small block in a much bigger stack, and capability comes from what you build around it.

11 — How it works

The ZenDesk Help Center pipeline

A second retrieval path, deliberately unlike the editorial one.

01

~700 articles, embedded straight from the ZenDesk API

A monthly sync batch-embeds every Help Center article into a dedicated Pinecone zendesk namespace — no Postgres round-trip. Support content stays isolated from editorial vectors.

02

search_help_center function tool

The agent calls it for account / billing / login / membership questions. Cosine-only ranking — no recency decay, no query rewrite: help articles are evergreen, and raw support phrasing embeds better than an editorial-style rewrite.

03

Prompt-level routing

The system prompt sends support questions to the Help Center and keeps gear / trail / training on the editorial RAG context — so the two corpora never cross-contaminate a single answer.

04

Help articles return as cited source cards

Retrieved articles ride back on the completed frame and render as source cards, deduped by URL alongside any editorial sources.

What the eval caught: the offline chat-eval ran the agent without threading the RAG client into the tool's run context, so search_help_center silently returned "no results" while tool_hit still reported 4/4 — the judge was scoring answers improvised from general knowledge.
